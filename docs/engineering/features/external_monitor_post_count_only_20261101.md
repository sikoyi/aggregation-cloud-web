# 外部账号仅展示帖子总数

2026-11-05 后续调整：按用户要求仅在外部监听主列表恢复粉丝数量及服务端升降序排序，使用已采集资料，不增加采集请求；详情、快照、日增量及总点赞/浏览量限制保持原样。

## 范围

- 外部监听列表、形象数据总览、账号详情与最近采集记录的账号级指标仅展示帖子总数。
- 移除粉丝、关注、总浏览量、总点赞等账号级指标展示与排序入口；保留帖子总数排序、日增量与千位缩写。
- 后端停止全账号帖子扫描和浏览量、点赞汇总，仅生成帖子总数快照与日增量。
- 保留账号身份、标签、国家、形象关联、监听状态、权限和所有历史记录。

## 不涉及

- 单帖原始互动指标、选题池门槛和排序、每周浏览量补采保持不变。
- 内部社媒账号数据、业务脚本、发布流程与生产环境不动。
- 发现计划所需的原生粉丝数据继续保留，不再作为外部监听统计列展示。

## 验收

- 旧资料中即使有汇总缓存，前端也不能再显示旧汇总；历史记录只呈现时间和帖子总数。
- 帖子数缺失显示 `--`，真实零显示 `0`，千位缩写沿用既有组件。
- 列表、形象账号对比与详情保持既有 `posts_count` 口径，不新增本地全量计数；底层归一化规则不变。
- 只调整已有测试断言与模拟，不新增测试文件或场景；本地验证后不自动推送或发版。

## 验证结果

- 128 个文件、1022 条既有前端测试通过，类型检查和生产构建通过。
- 50 项临时浏览器检查覆盖桌面、390px 窄屏、深色模式、单账号/形象总览/详情/历史、零/未知/千位缩写、切换成员与服务端帖子总数排序；旧汇总字段即使存在于响应中也不展示，无业务写请求或浏览器异常。
- 后端 344 条回归和 18 条 PostgreSQL 集成测试通过，另有 40 项数据库临时诊断确认停止汇总扫描、保留原始单帖指标及历史记录；无生产操作。
