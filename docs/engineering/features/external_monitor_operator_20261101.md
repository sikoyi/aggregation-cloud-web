# 外部账号操作员归属

## 已确认规则

- 团队在原平台权限内继续查看全部外部账号，仅负责人可维护，超级管理员可维护和分配全部。
- 新增默认归当前运营，管理员可选择、清空及批量调整操作员；历史账号保持未分配，创建人审计记录不改。
- 增加操作员列、筛选和新增/编辑字段。合并形象按实际成员显示操作员，部分筛选只描述当前匹配，不能借用首个成员的归属。
- 勾选、编辑、启停、删除、批量及形象关联按钮和处理函数均检查归属；形象整体维护使用后台的 `can_manage_persona`，不能用筛选后的部分成员推断权限。
- 未提供 `operator_id` 与明确为 `null` 分开处理，前者为未知，后者为未分配。普通运营不发送分配字段，旧后台缺少字段时禁止普通运营维护。

## 兼容与边界

- 操作员候选接口 404 时禁用分配/筛选，管理员原有元数据操作仍不携带不支持的字段。原本地后台保持 `http://127.0.0.1:8000`，不替换、不迁移。
- 临时请求失败保留已有候选、支持状态和当前筛选，不默默放宽到全体；明确 404 回退同时清空界面及实际请求的操作员条件。
- 禁用或无维护权限的历史操作员仍可显示/筛选，不可作为新分配目标；保持不变的历史归属编辑时不重新提交分配字段。
- 下拉控件把空字符串视为有效选项，“全部”“未分配”正确显示；批量清空仍明确发送一次 `operator_id: null`。
- 新增关联账号沿用原接口，默认归当前运营，不额外创建账号或重复采集。
- 不新增测试代码、文件或场景；按用户授权仅补充已有模拟状态和旧参数断言。不修改脚本、生产、原本地数据、密码或发布流程。
