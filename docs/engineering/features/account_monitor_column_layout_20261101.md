# 账号监听采集列排版修复

## 原因与范围

- 监听规则和最近采集结果分开展示后，表格仍沿用 170px 列宽，两个标签在内容区不能同排；多平台行用默认行内包装混排平台名和组件，平台名只有 10px，导致标签折行、对齐不一致和行高膨胀。
- 本地旧布局复现：列宽 170px，平台名 10px，两个状态标签的纵坐标分别为 729/753px，同身份两个平台的行高为 165px。
- 仅调整账号总览表格：列宽 230px，每个平台使用独立的纵向容器，平台名在上，状态标签居中同排；辅助文字 12px，长文字可安全换行。
- 异常详情按钮原本继承表格行高，约 29px，比普通标签 20px 高；在本列内统一为 20px，不影响其他页面的异常入口。

## 保持不变

- 监听已开启与最近采集结果继续独立展示，真实失败原因、发生时间和详情入口保留。
- 不改数据字段、状态计算、权限、采集、任务、原本地后台连接或生产环境。
- 原始本地数据不修改，不重跑任务，不新增或调整测试代码，不自动推送或发版。

## 验收

核对合并/展开的多平台账号、单账号、开启/关闭/异常/未配置、成功/失败/未知及旧接口缺少失败时间；桌面、深色、窄屏保持标签可读、无重叠，失败详情可正常打开且不触发采集或任务写请求。使用既有回归、类型检查、构建和临时浏览器诊断。

## 验证记录

- 128 个文件、1022 条现有前端测试、类型检查和生产构建通过；未修改或新增测试代码。
- 临时浏览器 59 项检查通过，覆盖 1920px 桌面、1440px 深色、390px 窄屏，普通/失败标签同排、边界不溢出、平台名称独立且不小于 12px、合并与展开、状态含义不变、旧接口缺少失败时间兼容、异常详情及北京时间。
- 同身份两个关闭平台的示例行高由 165px 降至 109px，两个标签纵坐标一致；异常按钮高度与标签统一为 20px。
- 窄屏沿用原固定列和横向滚动策略，展开及异常入口通过键盘激活验证；不扩大为整个表格响应式改造。
- 诊断所有 API 均拦截到本地模拟，真实业务写请求为 0；原后台和前端代理版本一致，原本地服务、数据库和生产不修改。
