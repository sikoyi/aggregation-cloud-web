# 多平台账号监听采集汇总

## 目标与设计

- 合并身份行不再在“监听 / 采集”列重复平台名称；平台仍在左侧平台列展示。
- 左侧平台链接按钮压缩为标签自身的 20px 高度，移除额外上下留白，保留点击和键盘操作。
- 合并行按“监听”“采集”两类汇总，同状态合并为一个计数标签；存在混合状态时分别保留数量，不用单个平台的结果覆盖整个身份。
- 异常停用和采集失败优先展示并标红。未配置监听的账号只计入监听分类，不虚构采集成功或失败；采集结果复用既有时间和错误判断。
- 未知监听状态按未配置汇总，没有监听设置 ID 时不计入采集分类；有明确设置 ID 时仍保留其已知采集结果。
- 汇总区域提供下拉图标、悬停提示和键盘焦点，点击或回车切换已有树表格展开；展开后的平台叶子继续使用原有状态和失败详情。

## 范围与边界

- 仅修改前端纯展示与本地树展开，不额外读取详情，不改变接口、权限、状态判断、后台配置、任务或原始数据。
- 单账号行、平台叶子及成功/失败时间和错误详情保持不变；计数只统计接口已返回且有权限查看的成员。
- 不新增或修改测试代码，不操作生产，不推送或发版。本地仍连接原后台，使用原 admin 环境。

## 验证

覆盖同状态 2/3 平台合并、混合开启/关闭/异常/未配置、成功/失败/未知、旧接口缺少失败时间、先失败后成功、合并/展开与错误详情、桌面/深色/窄屏及键盘交互；确认无业务写请求、状态不遗漏、数量一致、未配置不虚构采集统计。

## 验证记录

- 128 个文件、1022 条既有前端测试、类型检查和生产构建通过；没有新增或修改测试文件及场景。
- 80 项临时浏览器检查通过：1920px 桌面、1440px 深色、390px 窄屏，同状态合并为两个汇总标签、2/3 平台数量正确、混合状态和失败优先、未配置不虚构采集结果、旧接口与后续成功兼容、原单账号展示保留。
- 汇总按钮支持鼠标与回车展开/收起，展开标记及箭头同步，原失败详情和北京时间保留。原生悬停标题避免提示组件覆盖按钮的 `aria-expanded`。
- 同状态两平台示例行高不超过 80px、三平台不超过 100px；汇总标签保持至少 12px 且不越界。窄屏沿用原表格横向滚动和固定列，明细与异常入口使用键盘验证。
- 浏览器 API 全部拦截为本地模拟，业务写请求为 0，样式资源和浏览器运行无错误；不修改原本地数据、后台服务、账号密码或生产。
