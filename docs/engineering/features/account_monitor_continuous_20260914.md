# 账号监听连续设置

## 用户确认与边界

- 批量操作指保留窗口逐个连续保存，不是多选账号一次写入。
- 顶部开启监听窗口保存成功后保持打开，保留监听间隔和回复规则，清空当前账号及主页。
- 对标设置同样支持连续保存；对标主页不自动复用，避免关联到上一账号的对标来源。
- 总览逐行打开的锁定账号窗口仍按原行为保存后关闭。
- 业务 App 开放服务端已有监听实现的 Threads、X(Twitter)、Facebook，同时受用户平台范围限制。
- Instagram 监听未实现，不开放；Shopify 保留独立店铺监听，不混入社媒采集。
- 仅修改前端，不调整接口、权限、采集调度或执行端脚本。

## 保护措施

- 切换平台清空账号与主页，较早请求不能覆盖新选择或已关闭窗口。
- 提交时禁用账号、平台、配置切换与窗口关闭；主页读取期间禁止保存。
- 保存失败保留全部输入；保存成功清空选择，防止重复提交上一账号。

- 与 `AccountDataView.test.ts` 合计 12 项专项测试。
- `npm.cmd run build` 类型检查及构建通过，依赖已有 PURE 注解警告。
- 本地浏览器核对平台选项、X 账号树刷新、主页占位符及弹窗布局。
- 未保存真实账号监听、未调用外部采集；保存成功/失败通过模拟接口测试。现有本地 Vite 热更新生效，不重启后端。
